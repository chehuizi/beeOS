## 1. 产品定位

### 1.1 第一性定义

> **beeBox 是业务价值流在数字世界中的运行体。**

拆开看，三个词各管一段：

- **业务价值流**——一个端到端业务过程的"流动链"（如 接单 → 拉库存 → 分配仓位 → 出货）。有起点、有终点、有中间工序。
- **数字世界中的**——区别于物理车间，是数字化的、装在机器上的、可远程观察的。
- **运行体**——它在跑。启动后持续接收触发、持续流动、持续产出。不是文档、不是设计图、不是配置文件。

### 1.2 三个核心属性

| 属性 | 含义 |
|---|---|
| **业务价值流** | 跑的是什么——一个端到端业务的"流动链"（如 接单 → 生产 → 出货）|
| **持续流动** | 怎么跑——物料按工艺路线自动流转，不积压、不等待（精益的单件流）|
| **持续改善** | 跑出什么——运行时数据反哺业务改进（看板数据 → 调优 → 验证）|

> 三个属性缺一不可：
> - 少"业务价值流" → 退化成纯任务引擎
> - 少"持续流动" → 退化成批处理
> - 少"持续改善" → 退化成执行器

### 1.3 跟"非运行体"的关键差异

| 维度 | 非运行体（文档 / 设计图 / 配置） | **beeBox（运行体）** |
|---|---|---|
| 形态 | 静态描述 | 在跑 |
| 触发 | 人工启动 | 持续接收触发 |
| 流动 | 不流动 | 物料按工艺路线自动流转 |
| 反馈 | 无 | 看板数据 → 反馈到改善 |
| 异常 | 靠人盯 | 异常立刻暴露（看板）+ 自働化回流 |

### 1.4 在精益中的位置

- **精益 cell production**（小批量 / 单件流）= 业务价值流的**物理**实现
- **beeBox** = 精益 cell 的**数字**版本
- **对位关系**：1 个 beeBox = 1 个 cell；1 个 cell = 1 个业务价值流 ⇒ 1 个 beeBox = 1 个完整业务价值流
- **多个 beeBox 协同** = 多个 cell 组成完整工厂（v0.1 不涉及，cell 之间协同留待后续）

### 1.5 三个对立面（澄清 beeBox 不是什么）

| 对比对象 | beeBox 不一样在哪 |
|---|---|
| ❌ 业务流程文档 / SOP | SOP 是"描述跑法"的；beeBox 是"在跑"的 |
| ❌ 通用工作流引擎（Camunda / Airflow）| 工作流引擎只编排任务；beeBox 自带业务语义（库区 / 物料 / 看板 / 改善循环）|
| ❌ RPA（机器人流程自动化）| RPA 模拟"人在哪个软件点哪里"；beeBox 编排"业务怎么流动"——RPA 改操作，beeBox 改业务 |
